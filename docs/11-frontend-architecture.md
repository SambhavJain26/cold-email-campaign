# Frontend Architecture - React SPA

Stack locked in decision S: React 18 + Vite + TS + Tailwind + shadcn/ui + TanStack Query v5 + React Router v6 + react-hook-form/zod + Recharts + lucide-react + MSW. Lives in `apps/web/`.

---

## 1. Folder structure

```
apps/web/src/
├── main.tsx  app.tsx  router.tsx
├── api/
│   ├── client.ts          # fetch wrapper: /api/v1 base, credentials:'include',
│   │                      #   X-Requested-With header, error-envelope → AppApiError, zod-parse responses
│   ├── queries/           # one file per route group: useOverview(), useMailboxes(), useUnibox()...
│   │                      #   query keys = ['overview', campaignId] etc. - the ONLY place endpoints are called
│   └── mutations/         # useEnroll(), useTagSentiment()... each declares which query keys it invalidates
├── components/
│   ├── ui/                # shadcn generated primitives (button, card, dialog, table, tabs, badge, sonner…)
│   ├── layout/            # AppShell, SideNav, TopBar, AlertsBell, PageHeader
│   └── shared/            # MetricStat ("72 / 867 = 8.3%"), CapacityMeter, TierBadge, StateBadge,
│                          #   SentimentTag, Sparkline, DataTable (TanStack-free: plain table + our pagination),
│                          #   EmptyState, ConfirmTypedDialog, ProgressBar
├── features/              # one folder per screen (see docs/12): overview/ leads/ imports/ mailboxes/
│                          #   sequences/ campaigns/ unibox/ analytics/ coldstorage/ settings/ system/
├── lib/                   # formatters (dates, pct with numerator/denominator), tz labels, constants
├── mocks/                 # MSW handlers + golden-cohort fixture JSON (see §4)
└── e2e/                   # Playwright specs (walkthrough replay)
```

Rules: features may import `components/*`, `api/*`, `lib`; never each other. All server data flows through `api/queries` hooks - no raw `fetch` in features. All forms: react-hook-form + zod schema **imported from `packages/shared`** (the same schema the server validates with - decision H).

## 2. Routing & shell

```
/login                          (public)
/                               → redirect /overview
/overview                       📊  /leads  /leads/:id      📥
/mailboxes                      📧  /sequences /sequences/:id ✍️
/campaigns /campaigns/:id       🚀  /unibox                  💬
/analytics                      📈  /cold-storage            ♻️
/settings (tabs: rules|compliance|account)  ⚙️
/system (reply-detection debug + job status)
```

`AppShell` = fixed side nav (the walkthrough's 9 entries + System), top bar with campaign selector (global context: most screens are campaign-scoped; stored in URL `?campaign=`), AlertsBell (poll 30 s; unacked count badge; panel lists alerts with per-kind rendering). Auth guard: root loader calls `/auth/me`; 401 anywhere → redirect `/login` (handled centrally in `client.ts`).

## 3. Server-state conventions (decision T)

- Poll intervals: overview 30 s · unibox 60 s · mailboxes 60 s · alerts 30 s · others `refetchOnWindowFocus` only.
- Mutations invalidate the narrowest keys (e.g. tag-sentiment invalidates `['unibox']`, `['overview']`, `['analytics']`).
- Loading = skeleton rows (shadcn `Skeleton`), never spinners on full pages; errors = inline `EmptyState` with retry, plus toast for mutation failures showing `error.message` from the envelope.
- Optimistic updates **only** for Unibox tag + meeting-booked (the two one-click metrics - must feel instant); rollback on error.

## 4. MSW mock layer (what makes the F-track independent)

- `mocks/handlers.ts` implements **every** endpoint in docs/10 against in-memory fixture state derived from the golden cohort (`mocks/fixtures/golden/*.json`, generated by a backend script in B2 - task B2.18 - so mock numbers are the spec's numbers: 885/867/72/28/17…).
- Mutations mutate the in-memory state so flows are exercisable end-to-end offline (enroll decrements capacity, tagging updates positive rate, etc.).
- Enabled when `VITE_API_MODE=mock` (default for `npm run dev` until B6 lands; `real` proxies `/api` to `localhost:3000`). Playwright runs in **both** modes: mock mode in F-stage CI, real mode (backend + MockTransport) for integration (M3 gate).
- Failure-state fixtures: one handler set flips mailbox 3 to `auth_failed`, injects a `catchup_backlog` alert, an `auto_paused` mailbox - so F2/F8 failure panels are buildable without breaking anything for real.

## 5. Design system notes

- Tailwind + shadcn defaults, dark-mode-first (dashboard tool); accent color per state: green (positive/ok), amber (warning/paused), red (negative/failed), blue (info/nurture) - matching the walkthrough's 🟢🟡⚪🔵 tier glyphs (`TierBadge` renders those exact glyphs).
- Numbers are the product: `MetricStat` always renders `numerator / denominator = value%` on hover (title attr) with the headline value large - the spec's reconciliation transparency, in the UI.
- Tables: dense rows, sticky header, right-aligned numerics, tabular-nums.
- Charts: Recharts - `Sparkline` (tiny area, no axes) for 13d; bar/line only in Analytics. No pie charts.

## 6. Testing

- Component tests: Vitest + Testing Library for interactive pieces (CapacityMeter math display, Unibox card actions, import wizard steps, sequence builder validation).
- E2E: Playwright - the walkthrough replay spec (docs/13 §5) is the flagship; runs against mock mode per-PR and real mode nightly/at milestones.
